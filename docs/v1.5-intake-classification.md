# V1.5 Intake Classification

## Goal

Classify uploaded vendor-operation artifacts before extraction so downstream workflows can select the appropriate schema and review policy.

## Initial document classes

- `invoice`
- `purchase_order`
- `contract`
- `tax_document`
- `vendor_master`
- `unknown`

## Design principles

1. Classification is deterministic when strong filename/content signals exist.
2. Unknown or ambiguous documents must not be treated as trusted automation input.
3. Classification is persisted with the artifact/job lineage so later agent actions can audit why a route was selected.
4. The classifier is intentionally provider-agnostic; an LLM classifier can be introduced behind the same contract without changing the workflow boundary.

## Next implementation increments

- classifier contract and heuristic implementation
- extraction routing by document class
- OCR fallback for image-only documents
- page/document splitting with parent-child lineage
- field-level evidence and review queue
