# V1.4 — Production Object Storage & Intake Hardening

## Objective

Move uploaded source artifacts from an implicit local-filesystem assumption to a production-safe storage contract while preserving the existing local development/test adapter.

## Scope

- Define a storage provider contract with put/get/delete/existence operations.
- Preserve the local filesystem adapter for development and tests.
- Add an S3-compatible adapter using the standard AWS SDK interface.
- Scope object keys by tenant/workspace and artifact identity.
- Store content metadata and checksum for idempotency and integrity checks.
- Keep downloads private by default; signed access belongs behind the provider abstraction.
- Validate file content type and size before persistence.
- Avoid exposing raw storage paths through API responses.

## Acceptance criteria

1. Existing local tests remain green.
2. Production configuration can select S3 without changing pipeline code.
3. Objects are namespaced by workspace/tenant.
4. SHA-256 is calculated during ingestion and persisted with artifact metadata.
5. Re-uploading the same artifact can be detected deterministically.
6. Storage failures surface as typed application errors and do not create a falsely completed job.
7. No credentials are committed to the repository.
8. CI validates the storage adapter contract without requiring real cloud credentials.

## Out of scope for V1.4

- OCR implementation.
- Full agent runtime.
- ERP/procurement connectors.
- SSO/SAML implementation.

Those follow after the storage/intake boundary is production-safe.
