# V1.10 — Authorization + Policy Gate

V1.10 establishes the authorization boundary between agent planning and consequential tool execution.

## Security contract

- **Deny by default:** a tool is not executable merely because it is registered or discoverable.
- **Capability check:** the actor must possess every capability required by the tool, and the policy must explicitly allow those capabilities.
- **Risk ceiling:** the tool risk must not exceed the configured policy maximum.
- **Scope enforcement:** resource-scoped tools require a resource ID and can be restricted to an explicit resource allow-list.
- **Explicit write allow-list:** write actions must be named in `writable_actions`.
- **Approval binding:** consequential writes require an approval bound to the exact organization, workspace, action, tool version, payload, and resource.
- **Expiry:** an approval may expire and cannot authorize an action after its expiry time.
- **No approval replay:** changing the payload, resource, workspace, organization, or tool version changes the action fingerprint and invalidates the approval.

## Execution boundary

Call `PolicyGate.enforce(...)` immediately before handing an authorized request to an execution adapter. The execution adapter must not provide a bypass path around this gate.

V1.10 does **not** execute external side effects and does not yet persist approval grants. Durable approval records and execution receipts belong to the subsequent execution milestones.
