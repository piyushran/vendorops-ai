# V1.6 Agentic Workflow Foundation

VendorOps needs an explicit boundary between model reasoning and real-world side effects.

## Safety boundary

A vendor case may move into `executing` only after an explicit approval state. External integrations must implement actions behind this boundary and record the resulting outcome.

## Lifecycle

`received -> under_review -> ready_for_approval -> approved -> executing -> completed`

Failure is terminal from review, approval, or execution states until a future retry/reopen policy is explicitly implemented.

## Next increments

- persistent case state and audit events
- policy evaluation before approval requests
- tool/action registry
- idempotency keys for external actions
- execution result verification
- human approval API/UI
- integration adapter for the first AP/vendor workflow
