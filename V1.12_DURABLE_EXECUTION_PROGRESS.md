# V1.12 Durable Execution Progress

## Implemented

- DB-backed `DurableExecutionEngine` using the existing `AgentRun` and `ToolExecution` tables.
- Atomic database claim semantics for queued or expired runs.
- Worker lease owner and expiry fields.
- Execution state persisted before external side effects.
- Verification state persisted before independent verification.
- Heartbeat support for active tool leases.
- Expired execution recovery with adapter reconciliation by the original idempotency key.
- `needs_reconciliation` state when the adapter cannot safely determine the external outcome.
- Migration adding durable lease columns and indexes.
- Persistence, idempotency and crash-reconciliation tests.

## Acceptance boundary

A production ERP workflow is not complete until an external write followed by a simulated worker crash can be recovered by reconciliation without replaying the write.

ERPNext remains the reference connector for the first end-to-end test; Microsoft Business Central remains a later adapter behind the same execution contract.
